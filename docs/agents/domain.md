# 领域文档（Domain Docs）

各 engineering skill 在勘察代码前如何读取本仓库的领域文档。

## 探索前优先读这些

- 根目录 **`CONTEXT.md`**
- 根目录 **`docs/adr/`** —— 读与当前工作领域相关的 ADR

文件不存在就**静默跳过**，不要主动报缺、也不要建议预先创建。生产侧 skill（`/grill-with-docs`）会在术语/决策真正落地时按需创建。

## 文件布局

本仓库是 single-context 单一上下文：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
├── sdk_runtime.py
├── plugin.py
└── core/
```

## 使用术语表里的词汇

输出中提到任何领域概念（issue 标题、重构提案、假设、测试名）时，使用 `CONTEXT.md` 中给出的术语。不要漂移到术语表显式回避的同义词。

如果你需要的概念**还**没在术语表里——这是个信号：要么你在硬造项目不用的语言（重新考虑），要么这里确实有一个缺口（标记给 `/grill-with-docs`）。

## ADR 冲突要显式抛出

如果输出与已有 ADR 冲突，**显式标出**，不要悄悄盖过去：

> _与 ADR-0007（xxx）冲突——但值得重启讨论，因为……_
